# Explicit Scope & Known Limitations

1. **Enforcement Boundary**: Apodictic enforces invariants on traffic routed through `apodictic-sdk`, `apodictic-mcp-verifier`, or the PostgreSQL wire proxy (`apodictic_pg_proxy`). Direct database connections bypassing the gateway require database-level network/credential isolation.
2. **Database Concurrency**: 16-worker concurrent TCP solvency contention is verified against the compiled Rust `apodictic_pg_proxy` wire proxy (`3` allowed / `13` blocked with `SQLSTATE 40001` / `0` overdrafts; see `evidence/pg17-concurrency-receipt.json`). Transactional `SAVEPOINT ... ROLLBACK TO SAVEPOINT` + hidden PL/pgSQL `AFTER UPDATE` trigger rollback proofs are verified against real embedded PostgreSQL 18.7 (`@electric-sql/pglite`), with a `--pg-url` harness ready for dedicated external PostgreSQL servers; clustered multi-node production PostgreSQL benchmarks require dedicated external infrastructure.
3. **Formal Model Scope**: `formal-specifications.smt2` (`QF_LRA`) models financial reserve floors, 24-hour velocity caps, and tax parity. Both the native Rust compiler (`apodictic-symbolic-sql` powered by `sqlparser 0.64`) and Python enclave (`sqlglot`) preserve outer mutations containing subqueries, reject tautology `WHERE` predicates (`WHERE 1=1`, `WHERE 'a'='a'`), fold constant arithmetic, and unwrap CTEs (`WITH`), `DO $$ ... $$` PL/pgSQL blocks, and dynamic `chr()`/`hex` `EXECUTE` statements. Inside `apodictic_pg_proxy`, `--savepoint-mode` wraps upstream transactions in live `SAVEPOINT apodictic_sp_live` / `ROLLBACK TO SAVEPOINT` alongside multi-row double-entry (`account_move_line`), cross-branch POS inventory conservation (`stock_quant`/`stock_move`), and pricelist blast-radius guards (`product_pricelist_item`). For arbitrary out-of-band triggers in remote databases without live proxy `SAVEPOINT` mode or PGlite schema snapshots, schema synchronization is still required.
4. **External Validation**: Independent third-party penetration testing, blind external test corpora, and bare-metal Linux `/dev/kvm` Firecracker escape testing require external infrastructure/auditors.
