# Apodictic — Scope, Verification Boundaries & Known Limitations (v3.11.0)

Apodictic publishes verifiable receipts alongside explicit boundaries so enterprise buyers and auditors can evaluate what is proven today vs. what requires customer environment configuration or upcoming external audits:

1. **Network & Credential Boundary Required**: Every SQL write and ERP API call that traverses the Apodictic proxy (`apodictic_pg_proxy`, `wrap-odoo`, or SDK gateway) is verified before commit. Preventing out-of-band direct database writes bypassing the proxy requires standard customer VPC security-group / `pg_hba.conf` isolation restricting AI agent credentials exclusively to Apodictic's listener port (`5433` for Postgres, `8070` for Odoo).
2. **Continuous Live PostgreSQL 17 CI + 64-Worker Concurrency Proof**: Concurrent contention is verified in TWO layers and continuously tested on **live `postgres:17` (`PostgreSQL 17.12`)** in GitHub Actions CI (`verify-live-postgres17-and-redteam`):
   - `pg17-concurrency-receipt.json`: `16` concurrent TCP clients against the compiled Rust `apodictic_pg_proxy` (`3` allowed, `13` blocked with `SQLSTATE 40001`, `0` overdrafts) plus `16/16` hidden `AFTER UPDATE` PL/pgSQL trigger drains caught inside `SAVEPOINT` rollbacks.
   - `adversarial-redteam-receipt.json`: `64` concurrent TCP clients (`5` commits, `59` `SQLSTATE 40001` blocks, `0` overdrafts, exact `\$25,000` floor), `40/40` multi-engine bypass checks (`20/20` WASM Z3 5.4.1 + `20/20` isolated Python), `32/32` live trigger catches + `ON DELETE CASCADE` `SAVEPOINT` catches, `wrap-odoo` enforce/observe checks, `4/4` DLP checks, and `3/3` Ed25519 checks. Dedicated multi-node enterprise Postgres cluster chaos benchmarking remains customer-environment-specific.
3. **Hidden Database Triggers & Foreign-Key Cascades**: Pre-commit AST inspection alone cannot observe server-side triggers or `ON DELETE CASCADE` rules without execution. Enable `--savepoint-mode` in `apodictic_pg_proxy` (or auto-detect them first via `apodictic-mcp-verifier init --dsn ...`) so queries run inside a live `SAVEPOINT` and inspect post-trigger state before commit.
4. **PostgreSQL Wire-Parser Fuzzing & Pre-Audit Status**: We continuously test `apodictic_wire_proxy` against **1,000,000** fuzzed wire frames & hostile SQL inputs (`evidence/fuzz-corpus-receipt.json`: `0` panics, `0` bypasses, bounded `16 MiB` frame cap) plus `512`-case `proptest` suites and publish our mapped CISO questionnaire (`evidence/ciso-soc2-readiness-packet.json`). However, **formal third-party SOC 2 Type II certification, external third-party penetration testing, and bare-metal Linux `/dev/kvm` Firecracker MicroVM escape audits have not yet been completed externally** and are scheduled on the Q1 2027 roadmap.
5. **Production Telemetry vs. Benchmark Suites**: The `10,000`-case (`TP=7,500`, `TN=2,500`, `FP=0`, `FN=0`) and `100`-case counterfactual benchmarks evaluate deterministic rules on controlled test suites. Customer-specific production false-positive tuning is measured per deployment by starting in non-blocking `--mode observe` and generating an executive HTML/Markdown `audit-report` before toggling `--mode enforce`.
6. **Connector Maturity Tiers**: PostgreSQL (14–18) and Odoo (18–20 `/json/2/` Bearer API, `apodictic_odoo_guard` addon, & JSON-RPC) connectors are production-validated in CI; standalone MCP stdio, Stripe, and LangGraph/OpenAI/Vercel AI framework wrappers are actively supported / Limited Availability across enterprise design partners.
